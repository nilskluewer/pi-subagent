@nilskluewer/pi-subagent · v0.5.0

One tool. A whole agent tree.

A subagent extension for pi that delegates work to isolated child processes: inline personas, forked context, parallel councils, a root-scoped budget, one shared permission gate, and sessions you can resume any time.

How a delegation runs

Six stations, from the first tool call to a resumable session. Watch it play, or step through.

  1. 1
    Delegate

    One tool, three modes

    The main agent calls subagent - single, parallel, or chain. Personas are inline system prompts; no setup files needed.

  2. 2
    Fork

    Context forking

    forkContext seeds children with sanitized parent history: user messages and final answers kept, thinking and tool noise dropped.

  3. 3
    Spawn

    Isolated pi processes

    Every agent is a real pi child process. Children can nest to depth 2; a root-scoped budget caps live agents at 4 across the tree.

  4. 4
    Gate

    One permission gate

    Dangerous commands from any depth are proxied over the coordinator socket and prompt in the root TUI - labeled with the agent's name.

  5. 5
    Report

    Capped envelopes

    Results return as [agent | model | status | session] envelopes, capped at ~1000 tokens with a pointer to the full session file.

  6. 6
    Resume

    Persistent sessions

    Every run is a session with parent/rootId lineage. Resume any agent later - it remembers everything.

Everything in the box

One extension, one tool. Each capability is opt-in per call or configurable in ~/.pi/agent/subagent.json.

Modes

Single · parallel · chain

  • Single: one persona, one task, one result.
  • Parallel: up to 8 tasks, 4 concurrent - ideal for review councils.
  • Chain: sequential steps; {previous} pipes the prior step's full output into the next.
Personas

Inline-first, files optional

  • Pass systemPrompt + name, model, tools, thinking directly in the call.
  • Skills can define whole expert councils in plain text - no agent files.
  • Named agents still supported: markdown + frontmatter in ~/.pi/agent/agents/.
Context

Fork the parent's history

  • forkContext: "none" | "all" | "N" - seed children with the last N turns.
  • Sanitized: user messages and final answers kept; thinking, tool calls, and tool output dropped.
  • Compaction-aware - forks what the parent actually sees, with a size warning above ~8k tokens.
Results

Envelopes with a token cap

  • Every result: [agent | model | status | session] + payload.
  • Capped at ~1000 tokens; precedence item > call > config > default, 0 disables.
  • Nothing is lost: the notice points at the child's session file for the full output.
Nesting

Depth 2 with a tree budget

  • Subagents can spawn subagents (default depth 2; set maxDepth: 1 to opt out).
  • Root-scoped budget: max 4 live children across the whole tree, FIFO queue, bounded wait.
  • Leak-proof leases: a crashed agent's slot frees automatically on socket close.
Safety

One shared permission gate

  • Dangerous bash (rm -rf, git reset --hard, sudo, …) prompts in the root TUI from any depth.
  • Prompts are labeled with the agent's name; concurrent requests serialize.
  • No UI available? Dangerous calls fail closed. Abort kills the whole process tree.
Sessions

Resume anything, any time

  • Every run persists as <id>.jsonl + meta with parent/rootId lineage.
  • Pass resume: "<id>" to continue an agent with its full memory - e.g. reviewer verifies your fix.
  • Aborted runs hand back the session id plus the last 10 completed messages for smart recovery.
Steering

Delegation policy & guidance

  • Default policy: explicit request only - "more research" is not permission to spawn.
  • Switch to "proactive" or any custom policy line in subagent.json.
  • Built-in orchestration rules: self-contained tasks, no blocking delegation, disjoint write sets.
Visibility

Live subagent panel in the TUI

  • Running rows above the editor show status, model, current tool, task, tokens, turns, and cost.
  • Finished rows disappear immediately; nested activity shows as a +N nested counter.
  • Ctrl+O on the running call streams any child's output live.

How it works underneath

  1. Real processes, not threads. Each subagent is pi --mode json -p --session <file>; the JSONL event stream drives rendering, the widget, and usage accounting. A crashing child can never take down your session.
  2. One coordinator socket per tree. The root owns a Unix socket that carries approval proxying, the live-children budget (hold-open leases - release is the OS closing the connection), and nested status counts.
  3. Env contract for nesting. PI_SUBAGENT_DEPTH, ROOT_ID, and the frozen tree policy travel via environment - children can't raise their own budget. PI_SUBAGENT_INHERITED_TOOLS lets MCP bridges re-activate the parent's selection.
  4. Sessions are the source of truth. ~/.pi/agent/subagent-sessions/ holds every child's full transcript and lineage metadata - resumable across your own sessions, forever.
